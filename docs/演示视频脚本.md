# 演示视频脚本

总时长目标 4 分钟左右（3 到 5 分钟区间内）。全片一个人出镜或者只录屏配音都可以，下面按"只录屏 + 配音"来写，操作和解说卡在同一时间轴上。

录制前先确认三件事：MySQL 服务已启动、`python app.py` 已经跑起来、浏览器打开 <http://127.0.0.1:5000> 并且页面数据加载完了。录屏建议 1920×1080，浏览器缩放到 100%，别把书签栏露出来。

---

## 第 1 段　开场（0:00 - 0:25）

**画面**：停在首页，鼠标不动，让观众先看整体。

**操作**：无。

**旁白**：

> 这是我们做的社交媒体谣言检测系统，题目是谣言检测界面设计。系统用 Flask 和 MySQL 做后端，用 TF-IDF 加逻辑回归做谣言判断，整个流程从数据采集一直做到人工复核。下面按首页从上到下介绍一下。

**备注**：这段语速放慢一点，25 秒足够说三句话。别一上来就点来点去。

---

## 第 2 段　统计与数据展示（0:25 - 1:00）

**画面**：鼠标依次划过四个统计卡片，然后下移到消息列表。

**操作**：鼠标悬停在"消息总数 50""待人工校验""已处理""已确认谣言"上；滚动到列表，鼠标停在第一行的概率进度条上。

**旁白**：

> 首页顶部是四个统计数字，消息总数、待人工校验、已处理和已确认谣言，数据都是从数据库实时统计的。下面是消息列表，按发布时间倒序分页，每页 10 条。每条消息显示正文摘要、来源平台、发布时间、模型算出的谣言概率和当前状态。概率那一列我做成了进度条，超过 0.5 显示红色，低于 0.5 显示绿色，扫一眼就能看出哪些消息需要重点看。

**备注**：念数字的时候让鼠标停在卡片上，观众视线才好跟。

---

## 第 3 段　关键字搜索（1:00 - 1:30）

**画面**：搜索区域。

**操作**：在关键词框输入"小区"→ 点"搜索"→ 列表刷新，右下角显示"共 5 条"→ 点"重置"恢复。

**旁白**：

> 这个是关键字搜索模块，支持三个条件组合，可以只填关键词，也可以配合谣言概率下限和人工性质一起筛。比如我搜"小区"，能筛出 5 条相关的消息，结果默认按概率从高到低排。点重置就回到完整列表。

**备注**：**不要搜"疫苗"**，50 条示例数据里没有这个词，会搜出空结果。演示就用"小区"。概率下限如果要填，填 0.5 或 0.6，别填 0.8 以上，模型输出的概率基本不超过 0.7。

---

## 第 4 段　详情页与可解释性（1:30 - 2:20）

**画面**：详情页，这一段的重点是"命中关键词"。

**操作**：点第一行的"详情"链接 → 进入详情页 → 鼠标停在概率条上 → 鼠标移到"命中关键词"那一项停 2 秒。

**旁白**：

> 点进详情页可以看到完整信息：消息全文、来源、发布时间、模型判定的概率，还有一项我个人觉得比较有用的，就是"命中关键词"。逻辑回归这种模型对每个词都有一个权重，我把这条消息的 TF-IDF 值和对应的系数按位相乘，取正贡献最大的几个词，就能看出模型是主要因为哪几个词把它判成可疑的。很多在线的检测工具只给一个"疑似谣言"的结论，不告诉人为什么，我们这一步相当于把判断依据摊开给用户看。

**备注**：这段是全场重点，语速可以慢一些。如果这条消息的关键词显示得不够明显，可以换一条概率更高的消息讲。

---

## 第 5 段　服务器检测（2:20 - 2:45）

**画面**：详情页底部的操作按钮区。

**操作**：点"服务器检测"→ 等 2 到 3 秒 → 绿色提示条出现 → 鼠标停在提示条上。

**旁白**：

> 底部的"服务器检测"按钮会重新跑一遍模型。点下去之后，后端读取这条消息的正文，调用模型算出概率，再把结果和命中关键词写回数据库，检测完页面上的概率和状态会一起刷新。

**备注**：等待的时候别冷场，那句"后端读取正文、算概率、写回数据库"正好用来填这 2 秒。

---

## 第 6 段　人工校验（2:45 - 3:25）

**画面**：详情页的校验按钮。

**操作**：点"判为非谣言"→ 弹出确认框，停 1 秒 → 点确定 → 页面刷新，状态变成"已处理"，三个按钮变灰不可点 → 点左上角"返回列表" → 点"已处理文本"标签页，看到刚才那条记录。

**旁白**：

> 模型给的概率只是参考，最终定性还是得靠人。这里有两个按钮，判为谣言和判为非谣言，点了之后会弹一个确认框，避免误点。提交以后这条消息的状态变成已处理，同时往已处理文本表里插一条记录，列表里就不会再出现它了。已经处理过的消息，检测按钮会自动禁用，因为人工判断过的结论不该再被模型覆盖。我们切到"已处理文本"这个标签页，可以看到刚才那条记录已经在里面了，表头也换成了处理结果和处理时间。

**备注**：确认框出现后停 1 秒再点确定，观众才看得清。这一步会改数据库数据，如果正式答辩前要保留干净的演示数据，记得提前备份或者演示完重建。

---

## 第 7 段　词云与收尾（3:25 - 4:00）

**画面**：滚动到首页底部的词云。

**操作**：滚动到词云，鼠标在几个大词上悬停（会有 tooltip 显示词频）→ 停止滚动。

**旁白**：

> 首页最下面是关键词词云，数据来自 keywords 表，字号大小对应词频。整个系统的数据链路是通的：爬虫把消息采进来存到原始消息表，预处理做清洗和分词，模型算出概率和关键词，人在界面上做复核，复核结果又变成可以继续训练模型的标注数据。以上就是我们的系统，谢谢观看。

**备注**：结尾那句"复核结果可以继续训练模型"是实话，`database.py` 里确实留了取标注样本的函数，但界面没做一键重训的功能，不要说成已经实现了。

## 附：录制检查清单

| 检查项 | 说明 |
| --- | --- |
| MySQL 是否启动 | 没启动的话接口全部报错 |
| 服务是否已启动 | 先跑 `python app.py`，控制台看到"数据库连接正常""模型文件已就绪" |
| 端口是否被占 | 报错就把 `config.py` 里的 `PORT` 改成 5001 |
| 示例数据是否完整 | 库被清过的话先跑 `python spider.py` 导数据 |
| 搜索演示词 | 用"小区"，不要用"疫苗" |
| 概率下限演示值 | 用 0.5 或 0.6，别用 0.8 以上 |
| 浏览器缩放 | 100%，别把书签栏和下载记录露出来 |
| 录制分辨率 | 1920×1080 |
| 时长控制 | 每段念完就停，超时优先压缩第 2 段和第 7 段 |
