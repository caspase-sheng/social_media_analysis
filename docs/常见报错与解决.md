## 第 1 条　'conda' 不是内部或外部命令

**现象**

在命令行里敲 `conda` 或者 `activate rumor_detection`，提示：

```
'conda' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

**原因**

conda 装在 `D:\conda`，安装的时候没有勾选"添加到系统 PATH"，所以普通命令行找不到它。这不是没装，是找不到。

**解决**

用完整路径调用，不需要改系统环境变量：

```bat
call D:\conda\Scripts\activate.bat rumor_detection
```

激活成功的标志是命令行提示符前面出现 `(rumor_detection)`。

如果懒得激活，也可以直接用环境里的解释器跑脚本，效果一样：

```bat
D:\conda\envs\rumor_detection\python.exe app.py
```

## 第 2 条　run.bat 中文乱码、后面的命令没执行

**现象**

双击 `run.bat`，前面几行提示是乱码，后面几条命令完全没执行，窗口一闪就退出了。用编辑器打开这个文件看，内容却完全正常。

**原因**

cmd 读取 `.bat` 文件用的是系统 OEM 编码，中文 Windows 下是 936（GBK）。文件如果保存成 UTF-8，中文那几个字节会被按 GBK 解释成乱码，字节错位以后连后面的命令都会被吞掉。这个坑隐蔽的地方在于编辑器显示正常，只有真正执行才出问题。

**解决**

`run.bat` 里只保留 ASCII 字符，提示信息全部用英文写。脚本开头的 `chcp 65001` 是为了让 Python 输出的中文日志能正常显示，和这个坑是两回事。

以后改这个文件，不要往里加中文注释。

## 第 3 条　ModuleNotFoundError（但 pip list 里明明有）

**现象**

```
ModuleNotFoundError: No module named 'jieba'
```

执行 `pip list` 检查，jieba 明明在列表里。

**原因**

包装坏了。进 `site-packages` 目录看一下就明白了：只剩一个 `jieba-0.42.1.dist-info` 文件夹，真正的代码目录没了。pip 看到 dist-info 就认为这个包已经装好了，不会重装。

这种情况一般是之前某次安装中断留下的残留。

**解决**

强制重装，加上 `--no-deps` 避免连带重装已经装好的依赖：

```bat
pip install --force-reinstall --no-deps jieba
```

**经验**：报"模块不存在"但 pip 显示已安装的时候，先去 `site-packages` 里确认文件到底在不在，别急着重装整个环境。

## 第 4 条　TF-IDF 矩阵全是零

**现象**

预处理脚本能跑完，不报错，但打印出来的 TF-IDF 矩阵每一行都是零，模型训练出来完全没有效果。

**原因**

中文文本没有分词，直接丢给了 `TfidfVectorizer`。它默认的分词规则是 `token_pattern='(?u)\b\w\w+\b'`，意思是只认两个及以上字母数字组成的串。一整段中文在它眼里就是一个整体，切不开，所以提取不出任何特征。

**解决**

中文必须先自己分好词，再用空格拼成一个字符串送进去。项目里的做法是先过 jieba 和停用词表，再用 `preprocess.cut_to_string()` 把词用空格连起来。

```python
vec = vectorizer.transform([preprocess.cut_to_string(text)])
```

**排查思路**：这类"不报错但结果全空"的问题，通常要回到参数默认值上去找，而不是怀疑数据本身。

## 第 5 条　Can't connect to MySQL server (2003)

**现象**

```
pymysql.err.OperationalError: (2003, "Can't connect to MySQL server on '127.0.0.1'")
```

**原因**

MySQL 服务没启动，或者端口不对。

**解决**

1. 打开"服务"（Win + R 输入 `services.msc`），找到 `MySQL84` 之类的服务名，确认状态是"正在运行"，不是就右键启动。
2. 或者用命令行启动：

```bat
net start mysql84
```

服务名以本机实际安装的版本为准，不确定的话在服务列表里搜 "mysql"。

3. 确认 `config.py` 里的 `DB_PORT` 是 3306。装 MySQL 的时候如果改过端口，这里要跟着改。

## 第 6 条　Access denied for user 'root'@'localhost'

**现象**

```
pymysql.err.OperationalError: (1045, "Access denied for user 'root'@'localhost' (using password: YES)")
```

**原因**

`config.py` 里的数据库密码和你本机 MySQL 的密码对不上。

**解决**

打开 `config.py`，把这一行改成自己本机的密码：

```python
DB_PASSWORD = "root"   # 改成自己的密码
```

如果提示是 `using password: NO`，说明密码字段是空的，同样是这个位置的问题。

## 第 7 条　Unknown database 'rumor_detection'

**现象**

```
pymysql.err.OperationalError: (1049, "Unknown database 'rumor_detection'")
```

**原因**

库还没建。`database.py` 里的引擎是带库名的连接串，库不存在就报这个错。

**解决**

执行建库脚本，它会先 `CREATE DATABASE` 再建三张表，库和表都存在的时候不会重复创建，可以放心重复执行：

```bat
python init_db.py
```

想确认建好没有，加 `--check` 参数检查一下。想推倒重建（**会清空数据**）就加 `--drop`。

## 第 8 条　MySQL server has gone away

**现象**

项目刚启动的时候一切正常，跑了一段时间以后接口开始偶尔报连接错误：

```
pymysql.err.OperationalError: (2006, "MySQL server has gone away")
```

**原因**

MySQL 有个 `wait_timeout` 参数，空闲超过设定时间的连接会被服务端主动关掉。而 SQLAlchemy 连接池里还留着这些已经失效的连接，下次取出来用就报错。

**解决**

建引擎的时候加两个参数（项目里已经加了）：

```python
create_engine(
    url,
    pool_pre_ping=True,   # 每次取连接前先 ping 一下，不通就换一个
    pool_recycle=3600,    # 连接用满一小时主动回收
)
```

`pool_pre_ping` 是主要的，`pool_recycle` 是双保险。加上以后这个问题就没再出现过。

## 第 9 条　Too many connections

**现象**

```
pymysql.err.OperationalError: (1040, "Too many connections")
```

接口连续访问一段时间以后开始报这个，重启服务能暂时恢复。

**原因**

`database.py` 里用的是 `scoped_session`，同一个线程拿到的是同一个 Session。Flask 每个请求一个线程，请求处理完如果不去 remove，Session 就一直挂在那个线程上，数据库连接也不还回去。请求攒多了，连接数就超了 MySQL 的上限。

**解决**

在 `app.py` 里注册 teardown，每个请求结束调一次 `close_session()`：

```python
@app.teardown_appcontext
def cleanup_session(exception=None):
    database.close_session()
```

**经验**：用 `scoped_session` 就必须配套写 teardown，这两件事是一体的，只写一半迟早出问题。

## 第 10 条　TemplateNotFound: index.html

**现象**

打开 <http://127.0.0.1:5000> 报错：

```
jinja2.exceptions.TemplateNotFound: index.html
```

**原因**

`templates/` 目录下的模板文件缺失，或者文件名拼错了。Flask 默认在项目根目录下的 `templates/` 里找模板。

**解决**

确认目录结构是这样：

```
rumor_detection_project/
├── app.py
├── templates/
│   ├── index.html
│   └── detail.html
└── static/
    ├── style.css
    └── script.js
```

注意 `templates` 和 `static` 必须和 `app.py` 在同一层，不能放到别的地方去。文件名区分大小写，写成 `Index.html` 一样找不到。

## 第 11 条　端口被占用（WinError 10048）

**现象**

启动服务时报：

```
OSError: [WinError 10048] 通常每个套接字地址(协议/网络地址/端口)只允许使用一次
```

**原因**

5000 端口已经被别的程序占用了。常见的是上一次的服务没关干净，窗口关了但进程还在。

**解决**

办法一，改端口。打开 `config.py`：

```python
PORT = 5001
```

办法二，找出来是谁占着。用管理员权限打开命令行：

```bat
netstat -ano | findstr :5000
taskkill /PID 进程号 /F
```

第二行的进程号换成第一行查出来的那个。

**顺带说一句**：Flask 开启 debug 模式时自动重载会起两个进程，换端口的时候容易冲突，所以 `app.py` 里是用 `use_reloader=False` 启动的。

## 第 12 条　模型还没准备好

**现象**

点界面上的"服务器检测"，弹出提示：

```
模型还没准备好：找不到模型文件 ...\models\tfidf_vectorizer.pkl，请先执行 python train_model.py
```

**原因**

模型文件不存在。`models/` 目录里的两个 `.pkl` 文件是训练脚本生成的，项目从别人那里拷过来、或者清理过目录以后就没有了。

**解决**

按顺序执行：

```bat
python spider.py          # 导数据（库里有数据可以跳过）
python preprocess.py      # 预处理
python train_model.py     # 训练，生成 models/ 下的两个文件
```

启动 `app.py` 的时候控制台会自检并打印"模型文件已就绪"，用这个确认。

## 第 13 条　页面空白但控制台不报错

**现象**

前端页面打开是空白的，或者列表一直显示"正在加载..."，浏览器控制台和 Flask 控制台都没有明显报错。

**原因**

这种情况最难查，因为你分不清是三种可能里的哪一种：

1. 接口根本没有返回数据；
2. 接口返回了，但字段名或结构和前端预期不一致；
3. 接口数据正常，是前端渲染出了错。

**解决**

项目里做了两件事来解决这个问题：

一是**后端启动自检**。跑 `python app.py` 的时候，控制台会先打印数据库通不通、模型文件在不在，一眼就能看出是不是环境问题。

二是**统一返回结构**。所有接口都返回 `{code, msg, data}`，code 为 0 才是成功，非 0 时 msg 里写明原因。

排查步骤：

1. 直接访问接口看返回值，比如浏览器打开 `http://127.0.0.1:5000/api/overview`，看有没有正常返回 JSON；
2. 如果接口正常，按 F12 打开浏览器控制台，看 Network 里对应的请求状态码和响应内容；
3. 如果请求都没发出去，说明是 JS 报错，在 Console 里看红色错误。

## 第 14 条　中文显示成问号

**现象**

数据库里存进去的中文，在 Navicat 或者网页上显示成 `???` 或者乱码。

**原因**

数据库或表的字符集不是 utf8mb4。

**解决**

1. 确认建库时指定了字符集，`init_db.py` 里用的是：

```sql
CREATE DATABASE IF NOT EXISTS rumor_detection
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_general_ci;
```

2. 确认 `config.py` 里的连接串带了 `charset=utf8mb4`：

```python
"mysql+pymysql://{user}:{pwd}@{host}:{port}/{db}?charset={charset}"
```

3. 读 CSV 的时候也要指定编码。示例数据是 UTF-8 带 BOM 保存的，用 `encoding='utf-8-sig'` 读，不然第一列会多出来一个不可见字符：

```python
pd.read_csv(path, encoding="utf-8-sig")
```

## 第 15 条　词云区域是空的

**现象**

首页最下面"关键词词云"那一块空着，什么都没有。

**原因**

有三种可能：

1. `keywords` 表里没数据，词频还没统计过；
2. ECharts 或词云插件的 CDN 加载失败（比如校园网访问不了 jsDelivr）；
3. 数据有但格式不对，`echarts-wordcloud` 要求的是 `{name, value}` 结构。

**解决**

1. 先执行预处理统计词频：

```bat
python preprocess.py
```

2. 浏览器打开 `http://127.0.0.1:5000/api/keywords`，确认能返回词列表。返回是空的话回到第 1 步。

3. 确认网络。项目里对这种情况做了兜底：如果 `echarts` 没加载出来，会自动换成用字号大小表示词频的纯文字云，界面上仍然能看到词，只是样子朴素一些。如果你连文字云都看不到，那就是数据的问题，不是网络的问题。

4. 如果是在没有外网的环境下演示，建议提前把 ECharts 文件下载到 `static/` 目录里，改成本地引用。

## 第 16 条　爬虫抓不到数据

**现象**

执行 `python spider.py`，六个源都提示抓取到的条数是 0，或者只有个别源有数据。

**原因**

这几个新闻站的页面结构或者接口字段改了、被反爬拦了，或者当前网络访问不了外网。真实网站的反爬策略经常变，这不是代码写错了。另外单个源偶尔返回 0 条是正常的，比如某个接口临时限流。

**解决**

六个源是各自独立的，一个抓不到不影响其他几个，控制台会分别打印每个源抓到多少条，先看是哪个源没数据。脚本里已经做了判断：六个源合起来一条都没抓到，就自动切到读本地 CSV。也可以手动指定数据源：

```bat
python spider.py --source web    # 只走真实抓取，看看每个源的情况
python spider.py --source csv    # 跳过网络，只读本地文件
```

`--source` 有三个取值：`auto`（默认，先抓再兜底）、`web`（只抓）、`csv`（只读本地文件）。另外 `--pages` 对支持翻页的新浪和中新网有效，多抓几页数据量更大。

如果抓到的中文是一屏乱码（像“鍥介”这种），那是页面声明的编码和实际内容对不上，`spider.py` 里的 `decode_html` 会按 UTF-8、页面声明、GB18030 的顺序自动试，正常不需要手动改。

演示前建议先跑一次确认数据进库了，别到台上才发现是空的。

## 第 17 条　pip 安装依赖太慢或者超时

**现象**

`pip install -r requirements.txt` 卡住不动，或者报超时。

**原因**

默认从 PyPI 官方源下载，国内访问慢。

**解决**

加清华源：

```bat
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

想永久生效的话可以配置一次：

```bat
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

## 第 18 条　概率筛选搜不出结果

**现象**

在搜索条件里把"谣言概率下限"填成 0.8，结果一条都搜不出来，但列表里明明有概率不低的消息。

**原因**

不是功能坏了。爬来的新闻（非谣言）概率大多落在 0.1 到 0.3，带明显传谣特征的消息才会高到 0.7 以上，能超过 0.8 的本来就不多。下限填得太高，相当于要求比模型给出的最高分还高，自然是空的。

**解决**

演示的时候把下限设成 0.5，能筛出概率偏高的一小批（当前库里大约二十来条）。这条不算 bug，但演示前知道一下能避免尴尬。

如果哪天发现概率又全挤在同一个值上，看第 19 条。

## 第 19 条　一大批消息的谣言概率都是同一个数

**现象**

库里一堆消息的谣言概率完全一样，小数点后四位都不差，比如连着二十多条都是 49.6%。改阈值、重启服务都没用。

**原因**

TF-IDF 的词表只由训练样本构成。早先训练数据只有 `data/sample_data.csv` 那几十条模拟数据，真实新闻里的词（亚运会、报价、铜牌这些）一个都不在词表里，于是新闻转向量后整行都是 0。逻辑回归对一个全零的输入只能输出 `sigmoid(截距)`，也就是一个常数——所有没被词表覆盖的消息就都得到同一个概率。

**解决**

把覆盖面更广的文本作为带标签样本一起训练，让词表看到真实新闻用词。项目里的做法是在 `train_model.py` 里增加第三个数据来源：爬虫抓来的新闻正文，按"热榜和滚动页的新闻是媒体发布的真实信息"这个假设统一当非谣言（来源名单写在 `config.NEWS_SOURCES`）。改完重跑：

```bat
python preprocess.py
python train_model.py
python predict.py --recheck    # 已经检测过的消息也要用新模型刷一遍
```

刷完再看概率就有区分度了。这一步必须在服务停了以后做，因为 `app.py` 进程里把模型缓存在内存里，停着不重启的话它还在用旧模型算。

**排查思路**：概率出现"完全一致的重复值"这种特征，一般不是数据问题，而是模型压根没用上这批数据，得回头查特征提取有没有覆盖到。

## 附：演示前检查清单

按这个顺序过一遍，能把大部分现场事故挡掉。

| 顺序 | 检查项 | 命令 / 操作 |
| --- | --- | --- |
| 1 | MySQL 服务是否启动 | 服务列表里看 MySQL 状态 |
| 2 | 库和表是否建好 | `python init_db.py --check` |
| 3 | 数据是否入库 | `python spider.py` 后看列表有没有数据 |
| 4 | 模型文件是否存在 | 看 `models/` 目录下有没有两个 `.pkl` |
| 5 | 服务能否启动 | `python app.py`，看到"数据库连接正常""模型文件已就绪" |
